Задание 1:
Задание решено без возможности запуска кода (п.1 и п. 2)
Проблема текущей структуры проекта:
Иммется монолитный фронтенд и монолитный бэкенд. Связь компонентов осуществляется с использованием API. Бизнес-функции проекта подразумевают разную частоту запросов к бекенду. От наиболее частых к наименее частым:
1. учёт лайков
2. авторизация
3. редактирование альбома
4. редактирование профиля). 
Также можно разделить данные проекта по степени важности:
1. персональные данные пользователя - самые важные. Должны быть скрыты от всех других пользователей.
2. альбом пользователя и лайки -  управление только своими  данными, для других пользователей доступ только в режиме просмотра

Для эффективной реализации проекта имеет смысл использовать разный набор технологий для каждой бизнес-задачи. Текущий код проекта усложнен, развивать проект затруднительно. 


Паттерн декомпозиции:
Webpack Module Federation - выбран исходя из назначеня сервиса - просмотр и управления альбомами. Ленту альбома можно загружать по мере прокрутки контента, при этом обеспечивается быстрая загрузка первого фрагмента. При этом выделенные микрофронтэнды можно развертывать независимо.

Разбивка монолита на микрофронтенды:
1. Сервис альбома и учёта лайков фотографий (album_microfrontend)
2. Сервис авторизации пользователя (auth_microfrontend)
3. Сервис профиля пользователя (profile_microfrontend)

Точкой входа в приложение является приложение host
